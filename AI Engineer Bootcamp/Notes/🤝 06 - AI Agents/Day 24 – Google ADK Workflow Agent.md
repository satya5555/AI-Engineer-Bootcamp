## 2. What is Google ADK?

Google Agent Development Kit (ADK) is a framework for developing, orchestrating, and managing AI agents.

It provides components to build individual agents and coordinate multiple agents into workflows.

**Core concepts:**

- `LlmAgent`: Creates an AI agent powered by an LLM.
    
- `SequentialAgent`: Executes agents one after another.
    
- `ParallelAgent`: Executes multiple agents concurrently.
    
- `LoopAgent`: Repeats agent execution for iterative tasks.
    
- `Runner`: Executes an agent or workflow.
    
- `SessionService`: Manages conversation sessions and state.
    
- `ToolContext`: Provides tools access to the current agent execution context.

## 4. LlmAgent

`LlmAgent` is the fundamental component used to create an AI agent.

An agent can have:

- A name
    
- A model
    
- Instructions
    
- Tools
    
- An output key
    

Example:

```
from google.adk.agents import LlmAgent

agent = LlmAgent(
    name="researcher",
    model="gemini-2.5-flash",
    instruction="Research the given topic.",
    output_key="research_output"
)
```

### What is output_key?

`output_key` stores an agent's response in the session state.

For example:

```
output_key="research_output"
```

The output can subsequently be accessed using:

```
{research_output}
```

This allows downstream agents to use information generated by previous agents.

## 5. SequentialAgent

A `SequentialAgent` executes multiple agents in a predefined order.

### Workflow

```
User Input
    |
    v
Researcher Agent
    |
    v
Analyst Agent
    |
    v
Writer Agent
    |
    v
Final Report
```

### Implementation

```
from google.adk.agents import SequentialAgent

research_workflow = SequentialAgent(
    name="research_workflow",
    description="Researches, analyzes and creates a report.",
    sub_agents=[
        researcher,
        analyst,
        writer
    ]
)
```

### Key Points

- Agents execute one after another.
    
- Each agent can use outputs from previous agents.
    
- Useful for tasks requiring a predefined sequence.
    
- The workflow is predictable and structured.
    

**Example use cases:** Research pipelines, document generation, content creation and data processing.

## 6. ParallelAgent

A `ParallelAgent` executes multiple independent agents concurrently.

### Workflow

```
                User Input
                    |
                    v
              ParallelAgent
             /      |       \
            v       v        v
       Technology Benefits Challenges
         Agent    Agent     Agent
            \       |       /
             \      |      /
                    v
              Combined Results
```

### Implementation

```
from google.adk.agents import ParallelAgent

parallel_research = ParallelAgent(
    name="parallel_research",
    description="Runs independent research agents.",
    sub_agents=[
        technology_agent,
        benefits_agent,
        challenges_agent
    ]
)
```

### Key Points

- Multiple agents execute concurrently.
    
- Suitable for independent subtasks.
    
- Can reduce overall execution time compared with sequential execution.
    
- Each agent can save its result using a separate output key.
    

**Example use cases:** Market research, competitive analysis, independent data analysis and multi-perspective research.

## 7. LoopAgent

A `LoopAgent` repeatedly executes its sub-agents until a termination condition is reached or the maximum number of iterations is exhausted.

### Workflow

```
       Start
         |
         v
    Writer Agent
         |
         v
   Reviewer Agent
         |
         v
   Is report approved?
      /       \
    No         Yes
    |           |
    v           v
  Retry       Stop
```

### Implementation

```
from google.adk.agents import LoopAgent

report_loop = LoopAgent(
    name="report_loop",
    description="Generates and reviews a report.",
    sub_agents=[
        writer_agent,
        reviewer_agent
    ],
    max_iterations=3
)
```

### Termination using ToolContext

The approval function uses `ToolContext` to signal that the loop should stop.

```
def approve_report(tool_context: ToolContext):
    tool_context.actions.escalate = True

    return {
        "status": "approved",
        "message": "Report approved successfully."
    }
```

### Key Points

- Supports iterative improvement.
    
- Useful for writer-reviewer workflows.
    
- `max_iterations` limits repeated execution.
    
- An escalation signal can terminate the loop.
    

**Example use cases:** Report generation, code review, quality assurance and iterative content refinement.

## 8. Session State and Data Sharing

Session state allows agents to share information during a workflow.

Example:

```
output_key="research_output"
```

A downstream agent can access the result through:

```
{research_output}
```

Optional state placeholders can be written as:

```
{review_feedback?}
```

The optional placeholder avoids an error when that state value is not yet available.

## 9. Runner and SessionService

The `Runner` executes an agent or workflow.

`InMemorySessionService` manages sessions in memory during application execution.

General execution flow:

```
Create SessionService
       |
       v
Create Session
       |
       v
Initialize Runner
       |
       v
Run Agent/Workflow
       |
       v
Retrieve Session State
       |
       v
Display Results
```

The project uses `runner.run_async()` to execute workflows asynchronously.

## 14. Interview Questions

**Q1. What is Google ADK?**

Google Agent Development Kit is a framework for building and orchestrating AI agents.

**Q2. What is the difference between SequentialAgent and ParallelAgent?**

SequentialAgent executes agents one after another, whereas ParallelAgent executes independent agents concurrently.

**Q3. What is LoopAgent?**

LoopAgent repeatedly executes its sub-agents until a termination condition is reached or its maximum iteration limit is reached.

**Q4. What is output_key?**

It stores an agent's output in session state so that other agents can access it.

**Q5. What is Runner in Google ADK?**

Runner is responsible for executing an agent or workflow and coordinating its execution with session management.

**Q6. What is ToolContext?**

ToolContext provides a tool with access to the current execution context, including session-related information and control actions.

**Q7. Why use ParallelAgent?**

It allows independent tasks to execute concurrently, potentially reducing total execution time.

**Q8. How can we stop a LoopAgent?**

A loop can stop when a termination signal is raised using `tool_context.actions.escalate`, or when the maximum iteration count is reached.

**Q9. What is the purpose of SessionService?**

It manages agent sessions and their state during execution.

**Q10. When would you use each workflow?**

- SequentialAgent: Tasks with dependencies.
    
- ParallelAgent: Independent tasks.
    
- LoopAgent: Tasks requiring repeated review and improvement.
